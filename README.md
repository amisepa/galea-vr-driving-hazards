# Reactive and predictive processes during unpredictable driving hazards in virtual reality

![Study overview: multimodal immersive VR recording, signal processing, and robust statistics / ML classification](figures/repo_banner.png)

Pre- and post-stimulus neurophysiology of unpredictable car collisions in immersive virtual
reality, recorded with the Galea multimodal headset (OpenBCI) integrated into a Varjo Aero HMD.

Cannard, C., & Yeşilbaş, D. (2026). *Reactive and predictive processes during
unpredictable driving hazards in virtual reality: an exploratory brain and body
study with multimodal neurophysiological monitoring.* Supported by the BIAL
Foundation. Preregistered at [osf.io/xuw34](https://osf.io/xuw34).

## Layout

| Folder | Contents |
|---|---|
| `pipeline/` | Per-subject preprocessing. `galea_pipeline_v6_EEG.m` is current; `functions/` holds the Galea-specific helpers (import, event renaming, polarity correction, bad-channel detection). `galea_pipeline_v5_ppg.m` produces the per-subject heart-rate exports (`ERP_PPG.mat`) the cardiac analysis reads. `convert_to_bids.m` converts the study data to BIDS + HED; `rebuild_erp_from_bids.m` regenerates the per-subject exports from the BIDS derivative; `verify_bids_roundtrip.m` checks the round-trip against the original exports. |
| `analysis/` | Group-level analyses. Everything named `run_final_*` operates on the repaired dataset and writes to `results_final/`. |
| `figures/` | The paper's figures, regenerated by `analysis/make_figures.m` (Figure 1 is a vector schematic; Figure 2 shows the plugin's two dialogs). |
| `results_final/` | Output of the current analyses. Superseded folders were removed; they are archived in the study's Proton Drive archive (`code_archive/results_superseded/`). |
| `data/` | `stim_sequences_delivered/` (the quantum-randomised 120-trial sequence actually delivered to each subject, copied from the acquisition drive), the exported classification dataset, and `random_stim_sequences/` (sequence-generation code and diagnostics). |

Study data (raw recordings, per-subject exports), grant/admin documents, the Unity VR program and archived code live on Proton Drive under
`DATA/IONS_Galea_VR_study/` (`study_data/`, `grant_admin/`, `unity_vr_program/`, `code_archive/`).

## The EEGLAB plugin

The EEGLAB plugin for importing and preprocessing Galea recordings — with its
step-by-step usage tutorial, sample data, and GUI screenshots — lives in its own
repository: **[amisepa/galea-eeglab-plugin](https://github.com/amisepa/galea-eeglab-plugin)**
(installable from the EEGLAB extension manager). It is developed and released
separately; this repository contains only the code needed to replicate the study.

## Replicating the study

End-to-end, in order. Every step writes its outputs into `results_final/`, and
each later step reads only what earlier steps wrote.

### Step 0 — Environment

1. **MATLAB R2026a** (earlier releases back to ~R2023b likely work; paths and
   functions used are base MATLAB + EEGLAB).
2. **EEGLAB** (the version used here ships in `galea_set_paths.m`'s default;
   point `paths.eeglab` at your own copy). Required EEGLAB extensions, which
   EEGLAB's extension manager can install: `clean_rawdata`, `ICLabel`,
   `dipfit`, and the plugin's own dependency
   [BrainBeats](https://github.com/amisepa/BrainBeats) for the PPG branch.
3. The three companion toolboxes, cloned next to this repository (the layout
   `galea_set_paths.m` expects — one folder containing this repository,
   `eeg_robust_statistics/`, `Ascent/`, `Robust-Correlations/`):
   - [amisepa/eeg_robust_statistics](https://github.com/amisepa/eeg_robust_statistics) (robust GLM, Yuen statistics, cluster correction)
   - [amisepa/Ascent](https://github.com/amisepa/Ascent) (aperiodic 1/f fitting)
   - [amisepa/Robust-Correlations](https://github.com/amisepa/Robust-Correlations) (H4 time-symmetry analysis; needs the [LIBRA](https://wis.kuleuven.be/stat/robust/LIBRA) toolbox on the path)
4. **Configure paths once**: open `galea_set_paths.m` and set the four defaults
   at the top (EEGLAB folder, the two toolboxes, the study-data folder). Every
   script in this repository takes its paths from that single file.

### Step 1 — Data

The raw and preprocessed recordings are openly available in BIDS format with
HED annotations at OpenNeuro (https://doi.org/10.18112/openneuro.ds008837),
mirrored at NEMAR (https://www.nemar.org). Download the dataset and point
`paths.data` in
`galea_set_paths.m` at the folder containing the per-subject exports.

The delivered quantum-random-number trial sequences are in
`data/stim_sequences_delivered/` (one CSV per subject) and inside the BIDS
events files; `data/random_stim_sequences/` holds the generation code and
diagnostics for the qRNG sequences themselves.

### Step 2 — Per-subject preprocessing

```matlab
galea_set_paths;                      % verify paths resolve
pipeline/galea_pipeline_v6_EEG.m     % per-subject EEG: import, causal filter, bad channels, ASR, ICA
pipeline/galea_pipeline_v5_ppg.m     % per-subject heart-rate exports (ERP_PPG.mat) for the cardiac analysis
```

Notes:

- `galea_pipeline_v6_EEG.m` is the current EEG pipeline; it calls the plugin's
  import and preprocessing functions subject by subject.
- The one-off repair `pipeline/fix_sub011_erp_export.m` has already been
  applied to the OpenNeuro data; you do not need to run it.

### Step 3 — Group analyses (in this order)

```matlab
analysis/rerun_final_stats.m          % time-domain GLM + permutation clusters (pre and post windows)
analysis/run_final_EEG_tf_causal.m    % time-frequency, causal, both normalisations
analysis/run_final_EEG_alday.m        % baseline-regressor sensitivity analysis
analysis/run_final_EEG_covariates.m   % exploratory moderator models
analysis/run_final_H4_tf_symmetry.m   % H4: per-participant time-symmetry of pre vs post
analysis/run_ML_classification.m      % Demet Yesilbas's LOSO EEG / EEG+HR classification
analysis/galea_group_analysis_PPG.m   % cardiac analysis
analysis/run_prereg_prestim_controls.m % preregistered pre-stimulus control analyses
```

Everything writes to `results_final/`. The classification analyses read
`data/galea_ML_dataset.mat` (already in the repository) and archive their
result .mat files to `results_final/ML/`.

### Step 4 — Figures

```matlab
analysis/make_figures.m               % all figures from results_final
```

Figure 1 is a vector schematic (`figures/figure1_overview.svg`),
already in the repository; everything else regenerates from the result files.

### Step 5 — Verify you reproduced the paper

Spot-check against the paper:

- Post-stimulus ERP: 2 significant clusters, the largest peaking at ~500 ms.
- Pre-stimulus ERP: no cluster survives correction.
- Time-frequency: 1 post and 1 pre cluster (no-normalisation), 1 post and 2 pre
  (GLM-baseline normalisation).
- H4 time-symmetry: 16/16 participants positive, trimmed mean r = 0.29.
- Classification: post-stimulus decoding well above chance; pre-stimulus at chance.

### Deviations you may see

- Your permuted cluster p-values will differ in the third decimal from the
  paper's (permutation seeds); the cluster structure should not.
- If your OpenNeuro download differs in folder layout from `paths.data`'s
  expectation, adjust the path defaults — nothing else is hardcoded.

## Two things worth knowing

**The sub-011 repair.** That participant's session was interrupted and recorded as two files.
Both `.mat` exports ended up containing the same short second session, so the subject entered
every EEG analysis as duplicated trials. `pipeline/fix_sub011_erp_export.m` rebuilds both from
the surviving epoched `.set` files, giving 53 collision / 35 no-collision unique trials. All
results here postdate that repair; results computed before it were discarded.

**`compute_mcc_fast.m`.** The cluster-correction routine in `eeg_robust_statistics` computes
cluster masses with a loop that is O(clusters × elements). That is fine on post-stimulus data,
which has a few large clusters, but a noise-like map produces thousands of tiny ones and it
stalls indefinitely — which affects the pre-stimulus window and most covariate models.
`analysis/compute_mcc_fast.m` is a drop-in replacement using `accumarray`, verified to give
identical output on the post-stimulus window.

## Dependencies

MATLAB (R2026a used here) with EEGLAB, plus
[eeg_robust_statistics](https://github.com/amisepa/eeg_robust_statistics),
[Ascent](https://github.com/amisepa/Ascent) (aperiodic fitting, no Python needed),
[BrainBeats](https://github.com/amisepa/BrainBeats) (heartbeat detection), and
[Robust-Correlations](https://github.com/amisepa/Robust-Correlations) (H4 time-symmetry analysis).

All script paths are configured in one place: edit the four defaults at the top of
`galea_set_paths.m` (EEGLAB, the two toolboxes, and the study data folder) and every
analysis and pipeline script picks them up.
